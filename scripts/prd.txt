# Overview

The COMP4702 Machine Learning Assignment project implements an end‐to‐end pipeline for classifying table‐tennis swings using wearable IMU statistics. This PRD has been updated to reflect that the codebase is already initialized, raw data is located at `data/raw/assignTTSWING.csv`, and the environment is managed via the Conda environment named `ml_assignment`. Rather than producing a PDF report, the focus is on generating a comprehensive `DOCUMENT.md` that details methodology, results, and ties every section back to COMP4702 lecture concepts.

# Core Features

* **Data Ingestion & Cleaning (ETL)**

  * **Location**: `data/raw/assignTTSWING.csv`.
  * **Unit Conversion**: Raw LSB → physical units (Week 3):

    * Acceleration \[g] = raw × (2/32768)
    * Angular rate \[°/s] = raw × (250/32768)
  * **Data Quality Rules** (Week 3 & 5):

    * Drop rows with NaN after type casting.
    * Exclude records where ‖a‖ > 30 g.
  * **Output**: Cleaned CSV at `data/processed/processed.csv`.

* **Group‐Aware Data Partitioning**

  * **Protocol**: Group hold‐out split by `player_id` using scikit‐learn’s `GroupKFold` (Week 4).
  * **Split Ratios**: 70 % train · 15 % val · 15 % test.
  * **Persistence**: JSON files in `splits/`: `train.json`, `val.json`, `test.json`.

* **Baseline Model: Random Forest**

  * **Library**: scikit‐learn’s `RandomForestClassifier`.
  * **Hyperparameter Search**: Optuna with 5‐fold `GroupKFold` (Week 5 & 9).

    * Search space:

      * `n_estimators`: 100–600
      * `max_depth`: {None, 5–15}
      * `max_features`: {√p, 0.5–1.0}
      * `min_samples_leaf`: 1–10
  * **Outputs**:

    * Trained model serialized to `models/rf.pkl`.
    * Feature importance (Gini) for interpretability (Week 9).

* **Advanced Model 1: LightGBM**

  * **Library**: LightGBM `LGBMClassifier`.
  * **Hyperparameter Search**: Optuna + 5‐fold `GroupKFold`.

    * Search space:

      * `num_leaves`: 31–255
      * `learning_rate`: 1e-3–0.3 (log scale)
      * `max_depth`: {–1, 4–12}
      * `feature_fraction`: 0.6–1.0
      * `n_estimators`: 200–2000
  * **Interpretability**:

    * SHAP summary plots (Week 10).
    * Partial Dependence Plots for top features.
  * **Outputs**:

    * Model: `models/lgbm.pkl`.
    * SHAP artifacts in `results/`.

* **Advanced Model 2: Sparse Gaussian Process**

  * **Library**: GPytorch (with PyTorch backend).
  * **Preprocessing**: PCA reduced to 20 components (Week 6); `sklearn.decomposition.PCA`.
  * **Sparse Approximation**:

    * RBF kernel, 1 000 inducing points.
    * Optimize lengthscale ℓ & noise σ² by marginal likelihood (Week 11).
  * **Uncertainty Evaluation**:

    * Reliability diagrams & Expected Calibration Error (ECE).
  * **Outputs**:

    * Model: `models/gp.pkl`.
    * Calibration plots in `results/`.

* **Evaluation & Metrics**

  * **Primary Metric**: Macro‐F1 on test set (Week 4; handles class imbalance).
  * **Secondary Metrics**: Accuracy, balanced accuracy, per‐class precision/recall (Week 4).
  * **Uncertainty Metrics**: Brier score + ECE for GP (Week 11).
  * **Statistical Confidence Intervals**: 1 000-sample bootstrap stratified by `player_id` for Macro‐F1 (Week 5).
  * **Diagnostic Artifacts**:

    * Confusion matrices (matplotlib) for each model.
    * SHAP summaries (LightGBM).
    * GP reliability curves.

* **DOCUMENT.md Generation**

  * Every figure, table, and code snippet must be referenced and described in `DOCUMENT.md`.
  * Structure mirrors COMP4702 lecture progression (Weeks 1–11) and assignment rubric sections (Analysis, Presentation, Techniques, Results, Discussion, Depth).
  * No PDF compilation step—`DOCUMENT.md` is the single living document for narrative, results, and course connections.

# User Experience

* **Users & Personas**

  * **ML Student**: Seeks a reproducible, theory‐grounded example of a COMP4702 pipeline.
  * **Course Staff/Instructor**: Verifies that each step ties back to lecture material without relying on notebooks.
  * **Technical Reviewer**: Ensures code runs in the `ml_assignment` Conda environment with up-to-date packages.

* **Key User Flows**

  1. **Environment Setup**

     * Activate Conda env:

       ```bash
       conda activate ml_assignment
       ```
     * Install latest libraries:

       ```bash
       conda install -y python>=3.10 pandas numpy scikit-learn lightgbm torch gpytorch shap optuna matplotlib seaborn joblib
       ```
  2. **Data Preprocessing**

     * Run:

       ```bash
       python src/etl.py \
         --input data/raw/assignTTSWING.csv \
         --output data/processed/processed.csv
       ```
     * Validates unit conversion and cleaning; logs counts of dropped/outlier rows.
  3. **Data Splitting**

     * Run:

       ```bash
       python src/split_data.py \
         --input data/processed/processed.csv \
         --output_dir splits/
       ```
     * Produces `splits/train.json`, `splits/val.json`, `splits/test.json`.
  4. **Model Training**

     * **Random Forest**:

       ```bash
       python src/train_rf.py \
         --splits splits/train.json splits/val.json \
         --output models/rf.pkl
       ```
     * **LightGBM**:

       ```bash
       python src/train_lgbm.py \
         --splits splits/train.json splits/val.json \
         --output models/lgbm.pkl
       ```
     * **Sparse GP**:

       ```bash
       python src/train_gp.py \
         --splits splits/train.json splits/val.json \
         --output models/gp.pkl
       ```
  5. **Evaluation & Artifact Generation**

     * Run:

       ```bash
       python src/evaluate.py \
         --models models/rf.pkl models/lgbm.pkl models/gp.pkl \
         --splits splits/test.json \
         --output_dir results/
       ```
     * Outputs confusion matrices, SHAP plots, GP calibration plots, and `results/metrics.csv`.
  6. **DOCUMENT.md Authoring**

     * Populate `DOCUMENT.md` sections by copying templates from `docs/sections/` and inserting results from `results/`.
     * Ensure each subsection references the specific lecture (e.g., “(Week 9: Bagging & Boosting)”), includes relevant figures, and explains why each decision aligns with COMP4702 theory.
     * Use the following structure:

       1. **Introduction & Philosophy** (tie to rubric; outline objectives).
       2. **Dataset Specification & Preprocessing** (detailed EDA & cleaning steps).
       3. **Modeling Techniques**

          * Random Forest (Week 9).
          * LightGBM (Week 9–10).
          * Sparse GP (Week 11).
       4. **Evaluation & Results** (metrics, diagnostic plots, CI).
       5. **Discussion & Depth** (bias/variance, interpretability, uncertainty).
       6. **Appendices** (hyperparameter grids, code snippets, assumptions).

* **UI/UX Considerations**

  * **Command‐Line–Driven**: All functionality via CLI—no interactive notebooks.
  * **Clear File Organization**:

    * `data/raw/assignTTSWING.csv` → `data/processed/processed.csv`
    * `splits/` (JSON)
    * `models/` (.pkl files)
    * `results/` (plots + `metrics.csv`)
    * `docs/sections/` (markdown templates)
    * Top‐level `DOCUMENT.md` (final narrative)
  * **Logging & Metadata**: Each script logs start/end timestamps, random seeds, and key parameter values to `logs/`.

* **System Components**

  1. **ETL Module (`etl.py`)**

     * Reads `data/raw/assignTTSWING.csv`.
     * Converts IMU LSB → (g, °/s).
     * Removes NaNs; filters outliers (‖a‖ > 30 g).
     * Writes `data/processed/processed.csv`.
  2. **Data Splitting Module (`split_data.py`)**

     * Loads `processed.csv`.
     * Uses `GroupKFold(n_splits=...)` stratified by `player_id`.
     * Splits into 70 % train · 15 % val · 15 % test; saves JSON indices.
  3. **Model Training Modules**

     * **`train_rf.py`**:

       * Loads train/val splits.
       * Applies `StandardScaler` to numeric features (Week 6).
       * Uses Optuna + 5-fold `GroupKFold` to tune Random Forest.
       * Trains final RF with best hyperparameters; serializes to `models/rf.pkl`.
     * **`train_lgbm.py`**:

       * Loads train/val splits; reuses scaler from RF.
       * Optuna + 5-fold `GroupKFold` to tune LightGBM (early stopping every 50 rounds).
       * Computes SHAP values for interpretability; saves SHAP summary.
       * Serializes model to `models/lgbm.pkl`.
     * **`train_gp.py`**:

       * Loads train/val splits; applies `StandardScaler`, then PCA (n\_components = 20).
       * Constructs GPytorch model with RBF kernel and 1 000 inducing points.
       * Optimizes ℓ & σ² via marginal likelihood (Week 11).
       * Saves trained GP to `models/gp.pkl`.
  4. **Evaluation Module (`evaluate.py`)**

     * Loads `models/*.pkl` and `splits/test.json`.
     * Applies identical preprocessing pipelines (scaler, PCA) to test set.
     * For each model:

       * Computes predictions, class probabilities.
       * Calculates Macro-F1, balanced accuracy, per-class precision/recall.
       * Generates confusion matrix plot (matplotlib).
       * For LightGBM: plots SHAP summary; for GP: reliability diagram & ECE.
     * Compiles metrics into `results/metrics.csv`.

* **Data Models & Storage**

  * **Raw Data**: `assignTTSWING.csv` with columns `stroke_id`, `player_id`, six raw IMU axes, precomputed stats, `testmode`.
  * **Processed Data**: Numeric columns converted to physical units; no NaNs; outliers removed.
  * **JSON Splits**: Lists of integer indices for train/val/test.
  * **Pickles**: Serialized Python objects containing fitted models, scalers, and PCA pipeline.
  * **Results Directory**: Contains PNG artifacts and final metrics CSV.

* **Dependencies & Environment**

  * Managed via Conda environment `ml_assignment`.

# Logical Dependency Chain

1. **ETL (`etl.py`) → Splitting (`split_data.py`)**

   * Must produce a clean `processed.csv` before generating consistent JSON splits.
2. **Splitting → Baseline Model (`train_rf.py`)**

   * Requires `train.json` & `val.json` and the fitted `StandardScaler`.
3. **Baseline Model Analysis → LightGBM (`train_lgbm.py`)**

   * RF’s insights (e.g., top features, distribution) can inform LightGBM’s hyperparameter ranges.
4. **LightGBM Artifacts → Sparse GP (`train_gp.py`)**

   * Use LightGBM’s feature importance to decide which features to retain in PCA (if needed).
5. **Trained Models → Evaluation (`evaluate.py`)**

   * Needs all three `.pkl` files and `test.json` to compute final metrics.
6. **Evaluation Artifacts → DOCUMENT.md**

   * Figures/metrics generated drive the narrative in each DOCUMENT.md section.

# Risks and Mitigations

* **Risk: Data Path Mismatch**

  * *Issue*: Users might expect `TTSWING.csv` whereas project uses `assignTTSWING.csv`.
  * *Mitigation*: Clearly document in `README.md` and `DOCUMENT.md` that `data/raw/assignTTSWING.csv` is the source.

* **Risk: Environment Inconsistencies**

  * *Issue*: Using “latest versions” could break reproducibility if future changes introduce incompatibilities.
  * *Mitigation*: Provide an explicit `environment.yml` with major version constraints (e.g., `scikit-learn >=1.2, <2.0`) and instruct users to recreate `ml_assignment` via:

    ```bash
    conda env create -f environment.yml
    ```

* **Risk: Overfitting in Hyperparameter Tuning**

  * *Issue*: Optuna may overfit to validation partitions.
  * *Mitigation*:

    * Use 5-fold `GroupKFold` with `player_id` held out.
    * Validate on held-out validation set before final test.
    * Report bootstrap CIs for Macro-F1 to quantify uncertainty.

* **Risk: Computational Load (Sparse GP)**

  * *Issue*: GP training may be slow on CPU only.
  * *Mitigation*:

    * Reduce PCA to 20 components.
    * Fix inducing point count at 1 000.
    * Monitor and log training time; consider early stopping if convergence stalls.

* **Risk: Incomplete Documentation**

  * *Issue*: Failing to link methods back to lecture content may lose marks.
  * *Mitigation*: Enforce that each subsection in `DOCUMENT.md` includes explicit citations, e.g., “(Week 9: Ensemble Theory)” and a brief summary of how it applies.

* **Risk: JSON Split File Corruption**

  * *Issue*: Manual editing or file corruption may misalign splits.
  * *Mitigation*:

    * Version‐control `splits/` directory.
    * Add a checksum check in `split_data.py` to validate JSON integrity before use.
