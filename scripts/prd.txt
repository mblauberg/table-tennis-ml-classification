# Overview

The COMP4702 Machine Learning Assignment project implements an end‐to‐end pipeline for classifying table‐tennis swings using wearable IMU statistics. This PRD has been updated to reflect that the codebase is already initialized, raw data is located at `data/raw/assignTTSWING.csv`, and the environment is managed via the Conda environment named `ml_assignment`. The project implements an enhanced ETL pipeline with signal processing techniques and group-aware data splitting to prevent data leakage. Rather than producing a PDF report, the focus is on generating a comprehensive `DOCUMENT.md` that details methodology, results, and follows a structured academic format.

## Problem Definition: 3-Class Swing Classification

**Target Variable**: `testmode` - A categorical variable representing table tennis swing types

**Classification Task**: 3-class classification problem with the following target classes:
- **Class 0**: "Air Swing" - Practice swings performed in the air without ball contact
- **Class 1**: "Full Power" - Maximum intensity shots with full power stroke technique  
- **Class 2**: "Stable" - Controlled, stable hitting with consistent technique

**Practical Application**: This classification enables coaching feedback by automatically distinguishing between practice motions, power shots, and controlled techniques from wearable IMU sensor data.

**Dataset Context**: Each row in `data/raw/assignTTSWING.csv` represents one table tennis swing motion with pre-computed statistical features from 6-axis IMU sensors (3-axis accelerometer + 3-axis gyroscope), labeled with the corresponding `testmode` value (0, 1, or 2).

## Enhanced Data Processing Strategy

### Signal Processing & Data Quality Pipeline

The project implements a **lecture-aligned cleaning pipeline** that addresses real-world IMU data challenges:

**1. Unit Conversion (Physics-Based)**
- **Rationale**: Raw IMU data is in LSB (Least Significant Bit) format requiring conversion to physical units
- **Implementation**: 
  - Acceleration: LSB × (2g / 32768) for ±2g range sensors
  - Angular rate: LSB × (250°/s / 32768) for ±250°/s range sensors
- **Benefit**: Enables physically meaningful outlier detection and cross-sensor comparison

**2. Signal Smoothing (Week 3 Concepts)**
- **Median Despike**: 3-point rolling median to remove single-frame sensor spikes
- **Butterworth Low-Pass Filter**: 5th-order filter with 20Hz cutoff (fs=200Hz sampling)
- **Rationale**: IMU sensors are susceptible to electromagnetic interference and mechanical vibrations
- **Implementation**: Zero-phase `filtfilt` preserves signal timing while removing high-frequency noise

**3. Advanced Missing Data Handling**
- **Linear Interpolation**: Applied to isolated numeric gaps before NaN removal
- **Categorical Cleaning**: Remove rows with '???' placeholder values in demographic categories
- **Rationale**: Preserves maximum data while ensuring quality for ML pipelines

**4. Physically-Motivated Outlier Removal**
- **Threshold**: ‖acceleration‖ > 16g (beyond sensor specification)
- **Rationale**: Table tennis motions rarely exceed 8-10g; values >16g indicate sensor malfunction
- **Implementation**: Euclidean norm of acceleration components after unit conversion

**5. Feature Engineering for ML Compatibility**
- **One-Hot Encoding**: Categorical demographics (age, playYears, height, weight) 
- **Column Pruning**: Remove temporal metadata (date, fileindex, teststage, count)
- **Standardization**: Prepare features for scikit-learn Pipeline compatibility

### Group-Aware Data Partitioning (Week 5 Best Practices)

**Two-Round StratifiedGroupKFold Implementation**:

**Round 1**: 5-fold SGKF → Extract 1 fold as test set (20%), remaining 4 folds as temp set (80%)
**Round 2**: 4-fold SGKF on temp set → Extract 1 fold as validation (20% of temp = 16% overall), remainder as training (64% overall)

**Final Ratios**: ~64% train / 16% validation / 20% test

**Critical Design Decisions**:
- **Group Column**: `player_id` ensures no player appears in multiple splits
- **Stratification**: Maintains class balance (`testmode` distribution) across all splits
- **Deterministic**: Fixed random seed (123) for reproducibility
- **Leakage Prevention**: Player-specific swing patterns never leak between train/validation/test

**Rationale**: Standard train/test splits fail with grouped data because:
1. Players have consistent biomechanical patterns
2. Random splitting allows the same player in train and test
3. This leads to overly optimistic performance estimates
4. GroupKFold prevents this by ensuring complete player separation

# Core Features

* **Enhanced ETL Pipeline - Signal Processing + Data Quality**

  * **Location**: `src/etl.py` - Production-ready ETL module with comprehensive logging
  * **Input**: `data/raw/assignTTSWING.csv` containing raw table tennis swing data
  * **Target Preservation**: `testmode` column integrity maintained throughout all transformations
  
  * **Signal Processing Pipeline (Week 3 Concepts)**:
    * **Unit Conversion**: Raw LSB → physical units using sensor specifications
      - Acceleration [g] = raw × (2/32768) for ±2g range
      - Angular rate [°/s] = raw × (250/32768) for ±250°/s range
    * **Median Despike**: 3-point rolling median removes single-frame sensor artifacts
    * **Butterworth LPF**: 5th-order, 20Hz cutoff, zero-phase filtering for noise reduction
    * **Rationale**: IMU sensors require signal conditioning for reliable feature extraction
  
  * **Advanced Data Quality Rules**:
    * **Missing Data**: Linear interpolation for isolated gaps, then drop remaining NaNs
    * **Categorical Cleaning**: Remove rows with '???' placeholder values in demographics
    * **Physical Outliers**: Drop samples where ‖acceleration‖ > 16g (sensor malfunction threshold)
    * **Feature Engineering**: One-hot encode categorical demographics (age/playYears/height/weight)
    * **Column Pruning**: Remove temporal metadata (date, fileindex, teststage, count)
  
  * **Quality Assurance**:
    * **Deduplication**: Remove exact duplicate rows early in pipeline
    * **Target Validation**: Verify `testmode` integrity and class distribution
    * **Comprehensive Logging**: Detailed logs of every transformation step
    * **Output Validation**: Final dataset ready for GroupStratifiedKFold + scikit-learn
  
  * **Output**: `data/processed/processed_dataset.csv` - Clean, feature-engineered dataset
  * **Documentation**: Complete preprocessing methodology in `DOCUMENT.md` Section 2.3-2.4

* **Group‐Aware Data Partitioning (Week 5 Best Practices)**

  * **Implementation**: `src/split_data.py` - Two-round StratifiedGroupKFold approach
  * **Fundamental Principle**: Prevent data leakage by ensuring no `player_id` appears in multiple splits
  
  * **Two-Round SGKF Algorithm**:
    * **Round 1**: 5-fold SGKF → extract test set (20%)
    * **Round 2**: 4-fold SGKF on remainder → extract validation (16%)
    * **Final**: 64% train / 16% validation / 20% test with perfect group separation
  
  * **Critical Design Features**:
    * **Group Isolation**: `player_id` grouping prevents player-specific overfitting
    * **Class Stratification**: Maintains `testmode` distribution across all splits
    * **Deterministic Splitting**: Fixed random seed with deterministic ordering
    * **Leakage Prevention**: Player biomechanical patterns never leak between partitions
  
  * **Technical Implementation**:
    * **Library**: `sklearn.model_selection.StratifiedGroupKFold`
    * **Group Column**: `player_id` (93 unique players)
    * **Target Column**: `testmode` (0=air swing, 1=full power, 2=stable)
    * **Index Persistence**: JSON files preserve exact row indices for reproducibility
  
  * **Output Files**:
    * `splits/train.json` - Training set row indices 
    * `splits/val.json` - Validation set row indices
    * `splits/test.json` - Test set row indices
  
  * **Validation Benefits**:
    * **Realistic Performance**: Estimates generalization to new players
    * **Prevents Overfitting**: No memorization of player-specific patterns
    * **Statistical Validity**: Confidence intervals reflect true generalization uncertainty
  
  * **Documentation**: Splitting strategy and rationale detailed in `DOCUMENT.md` Section 2.5

* **Baseline Model: Multinomial Logistic Regression for 3-Class Classification**

  * **Library**: scikit-learn's `LogisticRegression` configured for multinomial (softmax) classification.
  * **Target**: Predicts `testmode` values (0=air swing, 1=full power, 2=stable) establishing the "linear ceiling" for comparison.
  * **Model Specification**:

    * `multi_class="multinomial"`: Single softmax model for 3 classes
    * `penalty="l2"`: Ridge regularization to control overfitting
    * `solver="saga"`: Handles L2, L1, and large sparse matrices
    * `class_weight="balanced"`: Offsets class-frequency imbalance
    * `max_iter=5000, tol=1e-4`: Guarantees convergence
  * **Hyperparameter Search**: Grid over inverse regularization strength C ∈ {10⁻³, 10⁻², 10⁻¹, 1, 10, 100}
  * **Cross-Validation**: 5-fold `GroupKFold` optimizing macro-F1 across all 3 swing types.
  * **Outputs**:

    * Trained 3-class linear model: `models/lr.pkl`.
    * Validation curve (F1 vs log₁₀ C): `results/val_curve_lr.png`.
    * Linear coefficient bar chart showing feature importance: `results/lr_coefficients.png`.
  * **Key Benefits**: Fast training, fully interpretable coefficients, establishes linear performance baseline.
  * **Documentation**: Linear baseline methodology in `DOCUMENT.md` Section 3.2

* **Advanced Model 1: Random Forest for 3-Class Classification**

  * **Library**: scikit‐learn's `RandomForestClassifier` configured for multi-class output.
  * **Target**: Predicts `testmode` values (0, 1, 2) representing swing types using ensemble of decision trees.
  * **Hyperparameter Search**: Optuna with 5‐fold `GroupKFold` optimizing for macro-F1 (equal weight to all 3 classes).

    * Search space:

      * `n_estimators`: 100–600
      * `max_depth`: {None, 5–15}
      * `max_features`: {√p, 0.5–1.0}
      * `min_samples_leaf`: 1–10
  * **Outputs**:

    * Trained 3-class ensemble model serialized to `models/rf.pkl`.
    * Feature importance (Gini) revealing which IMU features distinguish between swing types.
  * **Documentation**: Ensemble methodology in `DOCUMENT.md` Section 3.3

* **Advanced Model 2: LightGBM for 3-Class Classification**

  * **Library**: LightGBM `LGBMClassifier` optimized for multi-class swing type prediction.
  * **Target**: Predicts `testmode` values (0=air swing, 1=full power, 2=stable) with probability estimates for each class.
  * **Hyperparameter Search**: Optuna + 5‐fold `GroupKFold` optimizing macro-F1 across all 3 swing types.

    * Search space:

      * `num_leaves`: 31–255
      * `learning_rate`: 1e-3–0.3 (log scale)
      * `max_depth`: {–1, 4–12}
      * `feature_fraction`: 0.6–1.0
      * `n_estimators`: 200–2000
  * **Interpretability for Swing Classification**:

    * SHAP summary plots revealing which IMU features distinguish between air swings, power shots, and stable hits.
    * Partial Dependence Plots for top features showing their effect on each swing type probability.
  * **Outputs**:

    * 3-class trained model: `models/lgbm.pkl`.
    * SHAP artifacts in `results/` showing swing-type-specific feature importance.
  * **Documentation**: Gradient boosting methodology and SHAP analysis in `DOCUMENT.md` Section 3.4 and 4.4

* **Advanced Model 3: Sparse Gaussian Process for 3-Class Classification with Uncertainty**

  * **Library**: GPytorch (with PyTorch backend) configured for probabilistic multi-class classification.
  * **Target**: Predicts `testmode` probabilities (0, 1, 2) with calibrated uncertainty estimates for each swing type.
  * **Preprocessing**: PCA reduced to 20 components; `sklearn.decomposition.PCA`.
  * **Sparse Approximation**:

    * RBF kernel optimized for distinguishing between swing motion patterns.
    * 1 000 inducing points selected to capture swing type variability.
    * Optimize lengthscale ℓ & noise σ² by marginal likelihood.
  * **Uncertainty Evaluation for Coaching Applications**:

    * Reliability diagrams showing prediction confidence quality for each swing type.
    * Expected Calibration Error (ECE) quantifying uncertainty reliability.
    * Uncertainty estimates particularly valuable for identifying ambiguous swing patterns.
  * **Outputs**:

    * Probabilistic 3-class model: `models/gp.pkl`.
    * Calibration plots in `results/` showing uncertainty quality for each swing type.
  * **Documentation**: Bayesian methodology and uncertainty analysis in `DOCUMENT.md` Section 3.5 and 4.5

* **Evaluation & Metrics**

  * **Primary Metric**: Macro‐F1 on test set (optimal for 3-class classification; handles class imbalance by giving equal weight to each swing type).

# Risks and Mitigations

* **Risk: Data Path Mismatch**

  * *Issue*: Users might expect `TTSWING.csv` whereas project uses `assignTTSWING.csv`.
  * *Mitigation*: Clearly document in `README.md` and `DOCUMENT.md` that `data/raw/assignTTSWING.csv` is the source.

* **Risk: Environment Inconsistencies**

  * *Issue*: Using "latest versions" could break reproducibility if future changes introduce incompatibilities.
  * *Mitigation*: Provide an explicit `environment.yml` with major version constraints (e.g., `scikit-learn >=1.2, <2.0`) and instruct users to recreate `ml_assignment` via:

    ```bash
    conda env create -f environment.yml
    ```

* **Enhanced Risk: Signal Processing Complexity**

  * *Issue*: Butterworth filtering and median despike may introduce artifacts or remove important signal content
  * *Mitigation*: 
    - Use conservative filter parameters (20Hz cutoff for 200Hz sampling)
    - Implement zero-phase filtering to preserve temporal relationships
    - Document filter specifications and provide rationale in `DOCUMENT.md`
    - Log before/after statistics to verify signal preservation

* **Enhanced Risk: Group Splitting Complexity**

  * *Issue*: Two-round StratifiedGroupKFold may create imbalanced splits or fail with insufficient groups
  * *Mitigation*:
    - Validate minimum group sizes before splitting
    - Log group distribution across splits for verification
    - Implement fallback to simpler GroupKFold if stratification fails
    - Document group separation validation in evaluation

* **Risk: Overfitting in Hyperparameter Tuning**

  * *Issue*: Optuna may overfit to validation partitions.
  * *Mitigation*:

    * Use 5-fold `GroupKFold` with `player_id` held out.
    * Validate on held-out validation set before final test.
    * Report bootstrap CIs for Macro-F1 to quantify uncertainty.

* **Risk: Computational Load (Sparse GP)**

  * *Issue*: GP training may be slow on CPU only.
  * *Mitigation*:

    * Reduce PCA to 20 components.
    * Fix inducing point count at 1 000.
    * Monitor and log training time; consider early stopping if convergence stalls.

* **Enhanced Risk: Documentation Quality & Academic Standards**

  * *Issue*: `DOCUMENT.md` may lack sufficient technical depth or fail academic formatting requirements
  * *Mitigation*: 
    * Follow structured 8-section academic format with detailed methodology
    * Ensure 150-word abstract meets all requirements (objective, dataset, methods, results, insights)
    * Include comprehensive appendix with hyperparameters, assumptions, and code
    * Maintain professional academic tone with proper citations and references
    * Cross-validate all reported results against actual generated outputs

* **Enhanced Risk: Signal Processing Parameter Selection**

  * *Issue*: Filter cutoff frequency and outlier thresholds may be suboptimal for table tennis motion
  * *Mitigation*:
    * Base parameters on published literature for sports biomechanics
    * Document parameter selection rationale with physical justification
    * Implement parameter validation through signal-to-noise ratio analysis
    * Log filter impact statistics for transparency

* **Risk: JSON Split File Corruption**

  * *Issue*: Manual editing or file corruption may misalign splits.
  * *Mitigation*:

    * Version‐control `splits/` directory.
    * Add a checksum check in `split_data.py` to validate JSON integrity before use.
    * Implement group separation validation in evaluation scripts
