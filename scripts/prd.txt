# Overview

The COMP4702 Machine Learning Assignment project implements an end‐to‐end pipeline for classifying table‐tennis swings using wearable IMU statistics. This PRD has been updated to reflect that the codebase is already initialized, raw data is located at `data/raw/assignTTSWING.csv`, and the environment is managed via the Conda environment named `ml_assignment`. Rather than producing a PDF report, the focus is on generating a comprehensive `DOCUMENT.md` that details methodology, results, and follows a structured academic format.

## Problem Definition: 3-Class Swing Classification

**Target Variable**: `testmode` - A categorical variable representing table tennis swing types

**Classification Task**: 3-class classification problem with the following target classes:
- **Class 0**: "Air Swing" - Practice swings performed in the air without ball contact
- **Class 1**: "Full Power" - Maximum intensity shots with full power stroke technique  
- **Class 2**: "Stable" - Controlled, stable hitting with consistent technique

**Practical Application**: This classification enables coaching feedback by automatically distinguishing between practice motions, power shots, and controlled techniques from wearable IMU sensor data.

**Dataset Context**: Each row in `data/raw/assignTTSWING.csv` represents one table tennis swing motion with pre-computed statistical features from 6-axis IMU sensors (3-axis accelerometer + 3-axis gyroscope), labeled with the corresponding `testmode` value (0, 1, or 2).

# Core Features

* **Data Ingestion & Cleaning (ETL) - Target: 3-Class Swing Classification**

  * **Location**: `data/raw/assignTTSWING.csv` containing table tennis swing data.
  * **Target Variable**: `testmode` column with values 0 (air swing), 1 (full power), 2 (stable) - the core 3-class classification task.
  * **Features**: Pre-computed IMU statistical features from 6-axis sensors (3-axis accelerometer + 3-axis gyroscope).
  * **Unit Conversion**: Raw LSB → physical units:

    * Acceleration \[g] = raw × (2/32768)
    * Angular rate \[°/s] = raw × (250/32768)
  * **Data Quality Rules**:

    * Drop rows with NaN after type casting.
    * Exclude records where ‖a‖ > 30 g.
    * Preserve target variable `testmode` integrity throughout cleaning process.
  * **Output**: Cleaned CSV at `data/processed/processed.csv` maintaining 3-class target distribution.
  * **Documentation**: Complete preprocessing details in `DOCUMENT.md` Section 2.3-2.4

* **Group‐Aware Data Partitioning for 3-Class Classification**

  * **Protocol**: Group hold‐out split by `player_id` using scikit‐learn's `GroupKFold` to prevent player-specific overfitting.
  * **Split Ratios**: 70 % train · 15 % val · 15 % test while maintaining class balance across swing types (air/power/stable).
  * **Critical Constraint**: Ensure no `player_id` appears in multiple splits to avoid data leakage and realistic performance estimation.
  * **Class Preservation**: Stratify splits to maintain representative distribution of all 3 swing types in each partition.
  * **Persistence**: JSON files in `splits/`: `train.json`, `val.json`, `test.json`.
  * **Documentation**: Splitting strategy detailed in `DOCUMENT.md` Section 2.5

* **Baseline Model: Multinomial Logistic Regression for 3-Class Classification**

  * **Library**: scikit-learn's `LogisticRegression` configured for multinomial (softmax) classification.
  * **Target**: Predicts `testmode` values (0=air swing, 1=full power, 2=stable) establishing the "linear ceiling" for comparison.
  * **Model Specification**:

    * `multi_class="multinomial"`: Single softmax model for 3 classes
    * `penalty="l2"`: Ridge regularization to control overfitting
    * `solver="saga"`: Handles L2, L1, and large sparse matrices
    * `class_weight="balanced"`: Offsets class-frequency imbalance
    * `max_iter=5000, tol=1e-4`: Guarantees convergence
  * **Hyperparameter Search**: Grid over inverse regularization strength C ∈ {10⁻³, 10⁻², 10⁻¹, 1, 10, 100}
  * **Cross-Validation**: 5-fold `GroupKFold` optimizing macro-F1 across all 3 swing types.
  * **Outputs**:

    * Trained 3-class linear model: `models/lr.pkl`.
    * Validation curve (F1 vs log₁₀ C): `results/val_curve_lr.png`.
    * Linear coefficient bar chart showing feature importance: `results/lr_coefficients.png`.
  * **Key Benefits**: Fast training, fully interpretable coefficients, establishes linear performance baseline.
  * **Documentation**: Linear baseline methodology in `DOCUMENT.md` Section 3.2

* **Advanced Model 1: Random Forest for 3-Class Classification**

  * **Library**: scikit‐learn's `RandomForestClassifier` configured for multi-class output.
  * **Target**: Predicts `testmode` values (0, 1, 2) representing swing types using ensemble of decision trees.
  * **Hyperparameter Search**: Optuna with 5‐fold `GroupKFold` optimizing for macro-F1 (equal weight to all 3 classes).

    * Search space:

      * `n_estimators`: 100–600
      * `max_depth`: {None, 5–15}
      * `max_features`: {√p, 0.5–1.0}
      * `min_samples_leaf`: 1–10
  * **Outputs**:

    * Trained 3-class ensemble model serialized to `models/rf.pkl`.
    * Feature importance (Gini) revealing which IMU features distinguish between swing types.
  * **Documentation**: Ensemble methodology in `DOCUMENT.md` Section 3.3

* **Advanced Model 2: LightGBM for 3-Class Classification**

  * **Library**: LightGBM `LGBMClassifier` optimized for multi-class swing type prediction.
  * **Target**: Predicts `testmode` values (0=air swing, 1=full power, 2=stable) with probability estimates for each class.
  * **Hyperparameter Search**: Optuna + 5‐fold `GroupKFold` optimizing macro-F1 across all 3 swing types.

    * Search space:

      * `num_leaves`: 31–255
      * `learning_rate`: 1e-3–0.3 (log scale)
      * `max_depth`: {–1, 4–12}
      * `feature_fraction`: 0.6–1.0
      * `n_estimators`: 200–2000
  * **Interpretability for Swing Classification**:

    * SHAP summary plots revealing which IMU features distinguish between air swings, power shots, and stable hits.
    * Partial Dependence Plots for top features showing their effect on each swing type probability.
  * **Outputs**:

    * 3-class trained model: `models/lgbm.pkl`.
    * SHAP artifacts in `results/` showing swing-type-specific feature importance.
  * **Documentation**: Gradient boosting methodology and SHAP analysis in `DOCUMENT.md` Section 3.4 and 4.4

* **Advanced Model 3: Sparse Gaussian Process for 3-Class Classification with Uncertainty**

  * **Library**: GPytorch (with PyTorch backend) configured for probabilistic multi-class classification.
  * **Target**: Predicts `testmode` probabilities (0, 1, 2) with calibrated uncertainty estimates for each swing type.
  * **Preprocessing**: PCA reduced to 20 components; `sklearn.decomposition.PCA`.
  * **Sparse Approximation**:

    * RBF kernel optimized for distinguishing between swing motion patterns.
    * 1 000 inducing points selected to capture swing type variability.
    * Optimize lengthscale ℓ & noise σ² by marginal likelihood.
  * **Uncertainty Evaluation for Coaching Applications**:

    * Reliability diagrams showing prediction confidence quality for each swing type.
    * Expected Calibration Error (ECE) quantifying uncertainty reliability.
    * Uncertainty estimates particularly valuable for identifying ambiguous swing patterns.
  * **Outputs**:

    * Probabilistic 3-class model: `models/gp.pkl`.
    * Calibration plots in `results/` showing uncertainty quality for each swing type.
  * **Documentation**: Bayesian methodology and uncertainty analysis in `DOCUMENT.md` Section 3.5 and 4.5

* **Evaluation & Metrics**

  * **Primary Metric**: Macro‐F1 on test set (optimal for 3-class classification; handles class imbalance by giving equal weight to each swing type).
  * **Secondary Metrics**: 
    - Overall accuracy across all 4 model types
    - Balanced accuracy (average per-class recall)
    - Per‐class precision/recall for each swing type (air swing, full power, stable)
    - 4x3 confusion matrices showing misclassification patterns between swing types
  * **Uncertainty Metrics**: Brier score + ECE for GP (particularly valuable for distinguishing ambiguous swing patterns).
  * **Statistical Confidence Intervals**: 1 000-sample bootstrap stratified by `player_id` for Macro‐F1.
  * **Diagnostic Artifacts**:

    * **4 model confusion matrices** (matplotlib) for each model showing swing type classification patterns.
    * **Linear coefficients** (Logistic Regression) showing direct feature-to-prediction relationships.
    * **Feature importance charts** (Random Forest) using Gini impurity rankings.
    * SHAP summaries (LightGBM) revealing which IMU features distinguish between air swings, power shots, and stable hits.
    * GP reliability curves with uncertainty estimates for each swing type prediction.
  * **Documentation**: Complete evaluation methodology in `DOCUMENT.md` Section 4

* **System Components**

  1. **ETL Module (`etl.py`)**

     * Reads `data/raw/assignTTSWING.csv`.
     * Converts IMU LSB → (g, °/s).
     * Removes NaNs; filters outliers (‖a‖ > 30 g).
     * Writes `data/processed/processed.csv`.
  2. **Data Splitting Module (`split_data.py`)**

     * Loads `processed.csv`.
     * Uses `GroupKFold(n_splits=...)` stratified by `player_id`.
     * Splits into 70 % train · 15 % val · 15 % test; saves JSON indices.
  3. **Model Training Modules**

     * **`train_lr.py`**:

       * Loads train/val splits.
       * Applies `StandardScaler` to numeric features; saves scaler for reuse.
       * Uses grid search with 5-fold `GroupKFold` to tune Logistic Regression regularization.
       * Trains final LR with best C parameter; serializes to `models/lr.pkl`.
       * Generates validation curve and coefficient importance plots.
     * **`train_rf.py`**:

       * Loads train/val splits.
       * Applies `StandardScaler` to numeric features (reuses scaler from LR).
       * Uses Optuna + 5-fold `GroupKFold` to tune Random Forest.
       * Trains final RF with best hyperparameters; serializes to `models/rf.pkl`.
     * **`train_lgbm.py`**:

       * Loads train/val splits; reuses scaler from previous models.
       * Optuna + 5-fold `GroupKFold` to tune LightGBM (early stopping every 50 rounds).
       * Computes SHAP values for interpretability; saves SHAP summary.
       * Serializes model to `models/lgbm.pkl`.
     * **`train_gp.py`**:

       * Loads train/val splits; applies `StandardScaler`, then PCA (n\_components = 20).
       * Constructs GPytorch model with RBF kernel and 1 000 inducing points.
       * Optimizes ℓ & σ² via marginal likelihood (Week 11).
       * Saves trained GP to `models/gp.pkl`.
  4. **Evaluation Module (`evaluate.py`)**

     * Loads all models: `models/lr.pkl`, `models/rf.pkl`, `models/lgbm.pkl`, `models/gp.pkl` and `splits/test.json`.
     * Applies identical preprocessing pipelines (scaler, PCA) to test set.
     * For each model:

       * Computes predictions, class probabilities.
       * Calculates Macro-F1, balanced accuracy, per-class precision/recall.
       * Generates confusion matrix plot (matplotlib).
       * For LR: plots coefficient importance; for RF: plots Gini importance; for LightGBM: plots SHAP summary; for GP: reliability diagram & ECE.
     * Compiles metrics into `results/metrics.csv`.

# Logical Dependency Chain

1. **ETL (`etl.py`) → Splitting (`split_data.py`)**

   * Must produce a clean `processed.csv` before generating consistent JSON splits.
2. **Splitting → Baseline Model (`train_lr.py`)**

   * Requires `train.json` & `val.json` and the fitted `StandardScaler`.
3. **Baseline Model Analysis → LightGBM (`train_lgbm.py`)**

   * LR's insights (e.g., top features, distribution) can inform LightGBM's hyperparameter ranges.
4. **LightGBM Artifacts → Sparse GP (`train_gp.py`)**

   * Use LightGBM's feature importance to decide which features to retain in PCA (if needed).
5. **Trained Models → Evaluation (`evaluate.py`)**

# Risks and Mitigations

* **Risk: Data Path Mismatch**

  * *Issue*: Users might expect `TTSWING.csv` whereas project uses `assignTTSWING.csv`.
  * *Mitigation*: Clearly document in `README.md` and `DOCUMENT.md` that `data/raw/assignTTSWING.csv` is the source.

* **Risk: Environment Inconsistencies**

  * *Issue*: Using "latest versions" could break reproducibility if future changes introduce incompatibilities.
  * *Mitigation*: Provide an explicit `environment.yml` with major version constraints (e.g., `scikit-learn >=1.2, <2.0`) and instruct users to recreate `ml_assignment` via:

    ```bash
    conda env create -f environment.yml
    ```

* **Risk: Overfitting in Hyperparameter Tuning**

  * *Issue*: Optuna may overfit to validation partitions.
  * *Mitigation*:

    * Use 5-fold `GroupKFold` with `player_id` held out.
    * Validate on held-out validation set before final test.
    * Report bootstrap CIs for Macro-F1 to quantify uncertainty.

* **Risk: Computational Load (Sparse GP)**

  * *Issue*: GP training may be slow on CPU only.
  * *Mitigation*:

    * Reduce PCA to 20 components.
    * Fix inducing point count at 1 000.
    * Monitor and log training time; consider early stopping if convergence stalls.

* **Risk: Incomplete Documentation**

  * *Issue*: `DOCUMENT.md` may lack technical depth or proper academic format.
  * *Mitigation*: 
    * Follow the structured 8-section format with detailed subsections
    * Ensure 150-word abstract meets all requirements (objective, dataset, methods, results, insights)
    * Include comprehensive appendix with hyperparameters, code snippets, and assumptions
    * Maintain professional academic tone throughout

* **Risk: Documentation-Code Mismatch**

  * *Issue*: Results in `DOCUMENT.md` may not match actual implementation or generated artifacts.
  * *Mitigation*:
    * Systematically populate `DOCUMENT.md` after each implementation phase
    * Verify all figure references point to actual files in `results/`
    * Cross-check performance metrics between code output and documented results
    * Include version control for both code and documentation changes

* **Risk: JSON Split File Corruption**

  * *Issue*: Manual editing or file corruption may misalign splits.
  * *Mitigation*:

    * Version‐control `splits/` directory.
    * Add a checksum check in `split_data.py` to validate JSON integrity before use.
