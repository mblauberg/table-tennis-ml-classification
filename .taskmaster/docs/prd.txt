# PRD: COMP4702 Machine Learning Assignment - Table-Tennis Swing Classification (REVISED)

## Overview

This document outlines the **refined** Product Requirements for the COMP4702 Machine Learning Assignment. The project **will implement** a streamlined end‐to‐end pipeline for classifying table‐tennis swings using wearable IMU statistics. This PRD prioritizes **demonstrating core ML concepts from lectures** while maintaining computational feasibility, emphasizing proper experimental design, model comparison, and statistical evaluation.

## Problem Definition: 3-Class Swing Classification

**Target Variable**: `testmode` - A categorical variable representing table tennis swing types.

**Classification Task**: A 3-class classification problem with the following target classes:
-   **Class 0**: "Air Swing" - Practice swings performed in the air without ball contact.
-   **Class 1**: "Full Power" - Maximum intensity shots with full power stroke technique.
-   **Class 2**: "Stable" - Controlled, stable hitting with consistent technique.

**Learning Objectives**: This classification task **will demonstrate**:
- Proper experimental design with nested cross-validation
- Bias-variance tradeoff through model complexity comparison
- Feature selection and dimensionality considerations
- Model evaluation with appropriate statistical validation
- Understanding of supervised learning fundamentals

**Dataset Context**: Each row in `data/raw/assignTTSWING.csv` represents one table tennis swing motion with pre-computed statistical features from 6-axis IMU sensors, labeled with the corresponding `testmode` value. The `id` column represents unique player identifiers, critical for proper group-aware splitting.

## Core ML Concepts Demonstrated

### 1. Experimental Design & Cross-Validation (Lecture Week 5)
- **Nested Cross-Validation**: Outer GroupShuffleSplit (80/20) + Inner StratifiedGroupKFold (5-fold)
- **Data Leakage Prevention**: Group-aware splits ensure no player appears in multiple splits
- **Unbiased Evaluation**: Hyperparameters selected on inner CV, final evaluation on held-out test set
- **Statistical Validity**: Proper separation of model selection and performance estimation

### 2. Bias-Variance Tradeoff (Lecture Week 3)
- **Low Complexity**: Logistic Regression (high bias, low variance baseline)
- **Medium Complexity**: Random Forest (balanced bias-variance)
- **High Complexity**: LightGBM with regularization (low bias, controlled variance)
- **Complexity Analysis**: Learning curves and validation curves to demonstrate tradeoff

### 3. Feature Engineering & Selection (Lecture Week 4)
- **Domain Knowledge**: Physics-based feature engineering for IMU data
- **Statistical Selection**: Univariate filtering, mutual information
- **Model-Based Selection**: L1 regularization, tree-based importance
- **Dimensionality Impact**: Comparison of performance vs. feature count

### 4. Model Evaluation & Comparison (Lecture Week 6)
- **Appropriate Metrics**: Macro-F1 (class imbalance), confusion matrices, ROC curves
- **Statistical Significance**: Confidence intervals where applicable
- **Model Interpretability**: Feature importance, decision boundaries
- **Practical Considerations**: Training time, prediction latency

## Hyperparameter Optimization Protocol

### Search Strategy
- **Method**: Optuna with TPE sampler (efficient Bayesian optimization)
- **Budget**: Reduced trial counts (LR: 25, RF: 30, LGBM: 35 trials)
- **Objective**: Macro-F1 score to handle class imbalance
- **Efficiency**: MedianPruner for early stopping of poor trials

### Inner Cross-Validation
- **Method**: 5-fold StratifiedGroupKFold within outer training set
- **Stratification**: Maintains class balance across folds
- **Grouping**: Ensures player separation (no data leakage)
- **Reproducibility**: Fixed random seeds for deterministic results
